# Nightweaver 0.3 guide

For owned application servers and direct standalone comparisons, see the [0.4 additions](v0.4-guide.md).

Existing plans continue to work. Newly read plans have schema version 1 and reject unknown fields. Already registered plans keep their pinned settings. No accounts, scheduled tasks or existing projects are changed by installing this release.

## Budgets, fallback and retries

Add these fields to a plan or OneShot template:

```json
{
  "schema_version": 1,
  "budgets": {
    "max_calls": 24,
    "max_seconds": 7200,
    "max_observed_tokens": 1000000,
    "idle_timeout": 300,
    "max_log_bytes": 16777216
  },
  "worker": {"kind": "codex"},
  "worker_fallbacks": [{"kind": "claude"}],
  "reviewer": {"kind": "claude"},
  "reviewer_fallbacks": [{"kind": "codex"}],
  "retry": {
    "initial_seconds": 2,
    "max_seconds": 60,
    "transient_attempts": 2,
    "repeated_failure_limit": 3
  }
}
```

`max_calls` counts attempted provider invocations (workers, reviewers and optional local advice), not every model request made inside a CLI. Missing executables also count as attempted invocations. OneShot planning occurs before a run and is outside its budget. `max_seconds` is wall time from first execution, including pauses and downtime. Limits persist through restart and `--retry`; retry does not refill them. Forking explicitly creates a new budget.

Observed-token limits prevent later calls after recorded usage reaches the cap. An in-flight call can overshoot; providers that omit telemetry remain **unknown** and cannot be token-capped accurately. This is not a dollar cap. Subscription charges, API costs and local electricity are not inferred. Use call/time limits alongside tokens.

Fallback uses only routes explicitly configured by the operator. It happens for provider unavailability, including authentication, quota and missing CLI errors; a failed product check remains a repair attempt. Sessions are cleared when routes change. Transient errors use bounded persistent delays. The watcher skips future deadlines while serving other eligible runs. Repeated identical errors with the same staged tree stop the loop; changing the implementation resets that streak.

## Context and guidance

```json
{
  "context_files": ["README.md", "PRODUCT.md", "DESIGN.md"],
  "repository_map": true
}
```

Only selected committed text is captured, from the pinned baseline: up to 16KB per file, 48KB total, plus the first 240 tracked filenames. Uncommitted changes and other projects are not silently included. Context records retain hashes of the captured text. Context never replaces the objective, protected checks or acceptance criteria.

```powershell
python -m nightweaver feedback RUN_ID "Keep keyboard navigation and the approved visual references."
python -m nightweaver fork RUN_ID --milestone 1 --worker codex
```

Guidance is persisted and included in subsequent worker/reviewer calls. Guidance arriving during verification sends the candidate back for repair. Saving guidance does not unpause or restart a blocked run. The desktop has an inline guidance field. A fork starts at accepted checkpoint 1 with the remaining milestones; checkpoint 0 starts from the original baseline. The original run, its evidence and source checkout remain intact. No milestones remain after the final checkpoint, so choose an earlier one.

## Browser journeys

Install the optional dependency with `python -m pip install -e ".[browser]"`. Install a browser with `python -m playwright install chromium`, or select an installed `msedge` channel.

```json
{
  "name": "Search and mobile layout",
  "kind": "browser",
  "timeout": 90,
  "browser": {
    "page": "index.html",
    "heading": "Prompt Atlas",
    "channel": "msedge",
    "steps": [
      {"action": "fill", "selector": "#search", "value": "cinematic"},
      {"action": "click", "selector": "#apply"},
      {"action": "visible", "selector": "#results"}
    ]
  }
}
```

Selectors are project-specific. Available actions: `click`, `fill`, `press`, `check`, `visible`, exact `text`, and `count`. Default viewports are 1440×900 and 390×844; override `viewports` with named width/height objects. Each viewport gets an isolated browser context. Screenshots, traces and a JSON receipt are saved outside the candidate worktree, including failed checks. The gate checks page status, uncaught exceptions, console errors, declared interactions and horizontal overflow. Screenshots capture the viewport, not an unbounded full page.

Use `url` instead of `page` for an already-running local app. Only explicit loopback HTTP(S) URLs are accepted; Nightweaver does not start arbitrary application servers. A static `page` starts an owned temporary loopback server. Screenshots and traces show browser behavior; visual taste still needs an explicit brief and independent review. Artifact limits default to 32MB per file and can be configured per gate.

## Gemini

Use `{"kind":"gemini","model":"YOUR_AVAILABLE_MODEL"}` for a worker, reviewer or planner. Install/authenticate the official Gemini CLI separately. The adapter uses headless streaming JSON and `auto_edit` for workers or `plan` for review/planning. A normal npm Windows launcher is resolved to its package's JavaScript entrypoint and run through Node, without composing a shell command.

Gemini's `profile_dir` is the **parent of its `.gemini` folder**, matching `GEMINI_CLI_HOME`. Claude/Codex retain their own profile conventions. Do not reuse a Claude configuration directory for Gemini.

```powershell
python -m nightweaver doctor --planner gemini --live
```

A passing parser/adapter test is not evidence that your Google account is authenticated. Use the live probe for that. The CLI controls actual model availability and permissions.

## Issues, metrics and reports

```powershell
python -m nightweaver issue template.json --repo OWNER/REPOSITORY --number 12 --output issue-plan.json
python -m nightweaver add issue-plan.json
python -m nightweaver metrics RUN_ID
python -m nightweaver events RUN_ID --after 0 --limit 500
python -m nightweaver events RUN_ID --all
python -m nightweaver report RUN_ID --output report.html --include-images
```

Issue intake runs only `gh issue view` and preserves template checks. It does not start a run, comment, create a PR or modify the issue. Authenticate `gh` to the intended account first.

The standalone report has no external assets or scripts. HTML is escaped; common credential formats are redacted. This is **not complete anonymization**: objectives, filenames, evidence and screenshots can contain private project information. Raw local provider logs are not automatically scrubbed or embedded. Image inclusion is optional, verifies saved hashes and has a total embed limit of 20MB. The desktop's Open report includes available verified screenshots.

Event cursors use the last returned `seq`, are ascending and can read the entire history. Metrics include all attempts, not just the latest 80 events. Idle/output process exits are 125/126; timeouts use 124. Owned process trees still use native Windows Job Objects.

## Repeatable benchmarks

Create a suite file next to the referenced task plans:

```json
{
  "name": "Prompt Atlas acceptance pilot",
  "seed": 42,
  "repetitions": 3,
  "tasks": [{"name": "Search repair", "plan": "search-task.json"}],
  "contenders": [
    {"name": "Codex worker", "worker": {"kind": "codex", "model": "YOUR_AVAILABLE_MODEL"}},
    {"name": "Claude worker", "worker": {"kind": "claude", "model": "YOUR_AVAILABLE_MODEL"}}
  ]
}
```

Every task plan must declare a wall-time budget. Define protected independent acceptance checks, freeze dependencies and model versions, and use the same acceptance criteria. Creation pins Git baselines and records a reproducibly shuffled run order. Every run has isolated worktrees and its own state. Creation does not consume model calls.

```powershell
python -m nightweaver benchmark create suite.json
python -m nightweaver benchmark run BENCHMARK_ID
python -m nightweaver benchmark report BENCHMARK_ID --output comparison.html
```

`run` executes the suite sequentially; it can be restarted without restarting completed runs. Blocked runs remain failures until explicitly retried. Reports retain every repetition and separate finished from planned counts. They do not declare a statistically significant winner. User-active minutes, visual ratings, external provider usage and exact CLI/model revisions require an accompanying experimental record.

Normal contenders measure **Nightweaver with that worker configuration**. To measure a standalone system such as AGTX, use `mode: "external"` and a `command` worker that launches that complete workflow. Nightweaver makes one outer attempt and checks its final worktree; the external command owns its internal retries and must leave changes uncommitted. Supply a trusted wrapper that fits this contract. Its internal API requests are not visible as Nightweaver provider calls. Do not compare the outer call counts as if they were equal compute.

## Verification record

The integration suite covers native process termination/recovery, failed-check repair, milestone continuation, independent review, budget persistence, provider fallback, durable retry deadlines, repeated-failure stopping, immutable context, feedback, checkpoint forks, event pagination, HTML escaping/redaction, bounded artifacts, idle/noisy children, issue intake and deterministic benchmark accounting. Browser-enabled tests run real Edge/Chromium journeys and require failure followed by a successful repair with fresh evidence. Fixture success is not a measured ranking of live AI models.
