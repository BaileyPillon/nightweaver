# Nightweaver 0.19 · Goal pursuit

Version 0.18 recovered a run after its runner died. It did not make a run finish a goal. An audit of 118 runs on one machine, 13 of them real work, showed that the most important loop, choosing the next piece of work, judging progress and deciding when to stop, was a person. Version 0.19 moves that loop into Nightweaver and fixes ten defects that the same audit found in the repair loop, the runtime and the browser path. It does not show that a OneShot beats a standalone coding agent, and nothing measured so far says it does.

## Why this release

The audit read 46 run databases holding 118 runs and 4,039 events, 2,270 of them excluding heartbeats. It also read 67 messages from the owner, planner logs and worker and reviewer evidence logs. Thirteen of the runs were real work with real models and no scripted worker. The rest were benchmark trials, release fixtures and early smoke tests, counted separately so fixtures do not inflate the success rate.

- **There was no outer loop.** 24 of the 67 owner messages were the person acting as the loop: nine were some form of "keep going" and fifteen repeated the same "research and implement the top ten" prompt. `goal` asked the planner for a plan once and nothing re-planned afterwards. A real run was one fixed plan of one to three milestones lasting two to 43 minutes.
- **It was not unattended.** 8 of the 13 real runs needed a human step-in after launch: a missing Git identity, a verifier bug, a logger crash, visual review, a stalled worker, authentication and an infeasible brief that had to be rewritten.
- **The newest real run failed in the open.** The CROW run produced zero accepted milestones in 34 minutes and 29.2 million reported tokens, about 12.7 million after correcting a counting error. Its only check confirmed that a report file existed. Its brief contradicted itself. The repeated-failure detector did not fire, and its third attempt changed nothing but was reviewed anyway.
- **Time went to workers.** Across the live runs, workers took 70% of the time, reviewers 15%, a local advisory model 4% and checks 2.6%. Only 48% of worker and reviewer time landed in an attempt that ended up accepted.
- **There is no head-to-head evidence that a OneShot beats standalone Codex or Claude Code.** The only matched run with the same model was a trivial Unicode search task. Both accepted it. Nightweaver took about 2.8 times as long and 4.8 times the tokens (n=1). The 35-run "head-to-head" pilot mostly measured AGTX, and every Claude cell in it was blocked by authentication. The one measured advantage was stronger acceptance gates catching false passes, and the standalone agents were never given the stronger gate. The long multi-milestone runs (24 to 43 minutes) have no standalone baseline, which is where orchestration ought to matter. Cost cannot be compared, because usage telemetry was missing for some contenders and inflated for resumed Codex sessions. This release adds an outer loop and fixes defects. It does not close that question.

## Research coverage

The review window for outside material was August 21 through November 21, 2026, and the local baseline was the 0.18 release at `a4c764e`. Three inputs fed the rankings.

**Field evidence.** Read-only queries of the 46 Nightweaver run databases found on the machine, the planner logs, the evidence logs of the CROW run, the project's earlier research notes and the owner's messages. Fixed-in-release statements come from commit history and the assistant's commentary, not from re-runs. Operator step-ins are inferred from run events plus that commentary. The cumulative-token explanation is inferred from log structure, not from provider documentation. Subscription-window effects are not visible in the run databases. The CROW run still in progress at the time is not counted.

**GitHub, Hacker News and blog research.** Issues, releases, READMEs and the search API on GitHub, Hacker News through its search API and thread pages, arXiv abstracts, vendor documentation and changelogs, and engineering blogs. Reddit was blocked for both search and fetch, and a third-party mirror returned one low-signal query before refusing further requests, so the Reddit communities for Claude, Codex, local models and agents were not covered. YouTube and X were seen only as search-result titles, without transcripts. Page text passed through a small summarizer, so numbers may be slightly off, and items seen only as search snippets are marked. User voice in this pass is GitHub issues and Hacker News only. This was a scoped search of publicly discoverable material.

**Literature.** arXiv, OpenReview and conference papers from 2025 and 2026, plus engineering posts from Anthropic, OpenAI, Cursor and METR, weighted to the last six months. Most studies use small or older models, planted bugs, or math and language tasks, so transfer to frontier coding agents and web interfaces is limited. Where a source says so, this document says so.

In the tables below, *preprint* marks a single arXiv study to treat as a strong hint, *vendor-reported* marks a figure from the vendor's own post, *user-filed* marks a GitHub issue that is one person's account, and *unverified* marks a claim seen only as a snippet or contradicted elsewhere.

## Top 10 issues fixed

| Rank | Defect | Fix | Evidence |
|---:|---|---|---|
| 1 | No goal-level loop. A run ended when its plan was exhausted, and a person chose what came next. | The last accepted milestone moves the run to judging. A judge scores the build and a planner adds waves until the goal is met or a stop rule fires. | 24 of 67 owner messages were the person acting as the loop. [Harness-of-Harness](https://arxiv.org/abs/2609.01481) (preprint, its own benchmarks). |
| 2 | The repeated-failure detector never fired. It hashed the reviewer's wording, so any paraphrase reset the count. | A failure is identified by phase, sorted failed gates and build tree, never by wording. The third identical failure stops the run with a stated cause. | 0 `repeated_failure_stopped` events in 118 runs. One run rejected the same "10/11 checks passed" output twice and logged a count of 1 both times. [Review at Anthropic](https://claude.dev/blog/solving-code-review-at-anthropic/) on round caps. Small models reproduced a near-identical program in 33–68% of conditioned retries ([preprint](https://arxiv.org/abs/2607.26117)). |
| 3 | An identical build tree was reviewed again. | A worker that changes nothing after a review rejection is stopped as `no_progress` without re-running checks or the reviewer. | CROW's third candidate tree matched the second, yet a full reviewer call followed (137 s, 519K tokens). [Review at Anthropic](https://claude.dev/blog/solving-code-review-at-anthropic/) re-reviews only the diff. [Codex #37304](https://github.com/openai/codex/issues/37304) (user-filed). |
| 4 | A usage limit blocked a run within seconds. | The provider's reset time is parsed and the run parks until 90 seconds after it, then resumes on its own. The attempt is refunded. `retry.max_parks` and `retry.max_park_seconds` bound the wait. | Claude cells in the audit ended 3 to 14 seconds after launch with subscription or organization errors. The run databases do not separate a usage limit from an account error, and weekly-window state is not visible in them, so this is the closest local evidence, not proof. [Claude Code workflows](https://code.claude.com/docs/en/workflows) limits auto-continue to interactive sessions. |
| 5 | Codex resumed-session tokens were counted 1.2 to 2.5 times. | Each session counts the difference between successive cumulative figures. The raw figure is kept as `reported_tokens`. | CROW reported 29.2M against about 12.7M real. Five affected runs reported 42.8M worker tokens against about 21.8M. Inferred from log structure, not from provider documentation. |
| 6 | A silent Codex stall ran to the full attempt timeout (1800 s by default) and cost an attempt. | Workers, reviewers, judges and planners stop after 900 s of silence. A stalled worker is retried in a fresh session with its attempt refunded, at most twice in a row. | Three stalls in 43 Codex worker calls cost 1,562 s. None of the 20 real plans set `idle_timeout`. Factory retries a stream silent for four minutes ([Factory Droid 1.0](https://factory.com/news/frontier-harness), vendor-reported). |
| 7 | An approval with prose before the JSON verdict counted as a rejection. | Verdict extraction takes the last balanced JSON object with the required key from prose or code fences. An unreadable answer is asked for once more before it rejects. | A DeepSeek approval with a preamble was rejected, a 27 s worker call changed nothing, and the second review passed. 1 of 6 review rejections in live runs was a format failure. [Claude Code workflows](https://code.claude.com/docs/en/workflows) retries schema violations. |
| 8 | A missing bundled Chromium blocked every browser gate. | A gate that uses the bundled default retries with Microsoft Edge, then Chrome. `doctor` reports browser readiness. An explicit channel still fails closed. | A missing Chromium was a recurring setup failure. Version 0.8.0 scored a working page as rejected, and two later audit runs recorded "Chromium not installed". The receipt records the channel that ran because [environment differences alone can move more pixels than a real regression](https://dev.to/igrlk/fix-flaky-playwright-screenshot-tests-5ci0). |
| 9 | Chromium `debug.log` droppings rejected candidates. | Chromium logs, `.playwright-mcp/` and crash dumps absent from the base are no longer candidate changes. | A stray `debug.log` rejected a candidate after a 412 s worker call as a change outside the milestone paths. Local record only. |
| 10 | An expired Claude login silently collapsed review to the worker's own vendor. | A long-lived token is read from the user environment, the registry or a route file. An expired login blocks with the `claude setup-token` remedy. A same-vendor reviewer or judge is recorded as `independence_degraded`. | The login expired on 21 November, the next two planner calls used Codex, and the CROW reviewer was Codex reviewing Codex. The same-vendor penalty is contested: [self-preference](https://arxiv.org/abs/2604.06996) against [a reanalysis finding none](https://arxiv.org/abs/2610.00369) (both preprints). |

## Top 10 engineering improvements

| Rank | Change | Observable effect | Evidence |
|---:|---|---|---|
| 1 | The reviewer receives the full staged diff. | The patch is saved with the run and up to 16 KB is inline in the prompt. Before, the reviewer saw a diffstat. | Review quality falls on large diffs, which this does not chunk ([Bigger isn't always better](https://arxiv.org/abs/2606.15689), preprint, 150 samples). [METR](https://metr.org/notes/2026-03-10-many-swe-bench-passing-prs-would-not-be-merged-into-main/): maintainers would merge about 24 points fewer grader-passing patches. |
| 2 | The reviewer opens the screenshots. | Codex receives `--image`, Claude reads the files, and the prompt names each image. | A human found a visual regression in 2 of 4 runs with no reviewer. Opus caught 2 in 5 runs. Soft "look at the screenshots" instructions were followed about half the time ([screenshot loop](https://dev.to/yureki_lab/how-i-gave-my-ai-coding-agent-eyes-a-screenshot-feedback-loop-for-ui-work-jce)). This release has not measured how often reviewers open them. |
| 3 | The reviewer sees its earlier findings and blocks only on what matters. | The prompt lists prior REVISE findings with an instruction not to repeat nitpicks. | [Review at Anthropic](https://claude.dev/blog/solving-code-review-at-anthropic/) never re-posts findings (vendor-reported). [Ask HN setups](https://news.ycombinator.com/item?id=50366117): review agents "almost always find something". |
| 4 | Local Qwen advice runs before review and feeds the reviewer and the next worker. | The note reaches both prompts. Before, it was logged and ignored. | All 12 `local_advice` events were followed straight by acceptance, at 4.2% of live time. A cheap scout's handoff drove the gains in [Scrouting](https://arxiv.org/abs/2608.04804) (preprint, 7B scout, different task). |
| 5 | Blocked messages are structured. | A blocked run leads with its cause, then the last failure, then the worker's own explanation. | The CROW block was not actionable, and the operator rewrote the brief 88 s later. [The nightly Ralph loop](https://cloudwired.dev/notes/the-nightly-ralph-loop) escalates one question with a recommended answer. |
| 6 | Edge warm-up and favicon tolerance. | A non-bundled browser takes one throwaway screenshot first, and a missing favicon is not a page error. | Edge's first screenshot takes about two seconds and its favicon request logs a 404, which the headless shell never does. [A flaky harness teaches agents to rerun](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/) (vendor post). |
| 7 | `git_timeout` and a 900 s floor for `git worktree add`. | A repository with 224,654 tracked files can be checked out, and a timed-out checkout is cleaned up and explained. | The CROW project blocked after 3:56 on a 90 s limit. The workaround moved its data outside Nightweaver's isolation. |
| 8 | Credential hygiene across providers. | Codex and Gemini processes no longer inherit Claude, Anthropic or DeepSeek credentials, and Claude processes drop `DEEPSEEK_API_KEY`. | No local incident. Driven by outside reports: [auto mode is not a security boundary](https://embracethered.com/blog/posts/2026/breaking-claude-code-opus-5-and-automode/), and ["Don't Ask Again" leaked secrets into public repositories](https://news.ycombinator.com/item?id=50407882) (Hacker News, unverified). |
| 9 | `db-check`, `doctor` and `preflight` understand pursuit. | They accept judging and planning runs, check the judge, its fallbacks and the planner, and report the Claude auth source and browser readiness. | The audit's fix direction for provider failures included a live check for every role. |
| 10 | Parked runs poll gently and resume through the runner, the dispatcher and the guard. | A parked run does not spin, and any of the three launch paths resumes it. | [Codex #41831](https://github.com/openai/codex/issues/41831): no waiting state, 1,621 no-op turns in one run (user-filed). |

## Operating a pursuit

```powershell
nightweaver oneshot C:\src\project "Build a polished pricing page" --pursue --judge claude --judge-model claude-opus-5-5 --judge-effort xhigh --waves 3 --wait
nightweaver pursuit RUN_ID
nightweaver pursuit RUN_ID --add-waves 2
nightweaver report RUN_ID --output report.html
```

The judge is the part to watch. A judge from the worker's vendor is allowed but recorded. `target_score` defaults to 85 and `plateau` to two judgments that fail to beat the best. A stopped run keeps its best build on `nightweaver/<run-id>`, and `--add-waves` resumes it at the judge with a fresh plateau count. Each wave costs a planner call, a worker call per milestone and a judge call. Set `budgets` when spend matters. The README has the `pursue` block, the unattended-run settings and the Claude token setup.

## Not in this release

- **Pursuit UI and UX.** The dashboard names pursuit events in plain words, but it cannot start a pursuit, and it has no score curve or target-against-current view. That waits for an options round with the owner before anything is built.
- **Parallel best-of-N and design exploration.** Many small teams beat one large team in one paper, but with a 27B model on 12 tasks and a reliable verifier ([preprint](https://arxiv.org/abs/2611.09798)). A single-task experiment found a tournament cut input tokens by 67% against four sequential retries ([DEV post](https://dev.to/tappers_/escaping-sunk-cost-retry-loops-in-coding-agents-single-session-retries-vs-a-parallel-best-of-n-3p3i), one toy task). Pursuit is sequential, and its keep-best rule is the only selection.
- **A matched baseline benchmark.** The audit found no standalone baseline with the same gate and the same model. Until one runs for every release, the claim that orchestration helps stays unmeasured.
- **Lessons memory.** Unconsolidated memory eventually fell below a no-memory baseline in [Hippo](https://arxiv.org/abs/2610.24453), and reused memory caused regressions in [MemDev-Bench](https://arxiv.org/abs/2610.27524) (both preprints). A wrong note that gets trusted can loop an agent ([Anthropic on agent memory](https://anthropic.com/engineering/components-of-agent-memory)). A design that stores lessons with evidence and applicability conditions comes first.

## Verification

The four new test modules hold 134 tests, counted from the test methods and confirmed by test discovery: `test_release_019_pursuit` 25, `test_release_019_browser` 30, `test_release_019_runtime` 55 and `test_release_019_repair` 24. The whole suite holds 336 tests, up from 202 at 0.18. They use scripted workers, judges and planners and mocked provider processes, with no paid model requests. Nothing in this document is a measurement from a live run with real models. That comes next.
