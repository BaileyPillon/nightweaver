# Nightweaver 0.19.4 notes

0.19.4 fixes one bug: the goal planner was cut off after 240 seconds, whatever the template said. It also makes every message about a call that Nightweaver itself ended say what happened and which setting controls it.

## The bug

A real unattended run on 0.19.3, in a research repository, started with `nightweaver goal <template> --objective-file ... --planner antigravity --model gemini-4-neon --effort xhigh`. Twice it stopped about four minutes in with `Planner exited 124. See <log>`, even after the template's `agent_timeout` was raised to 5400 seconds. The planner was not failing. It was still reading: at extra-high effort on a large objective it opens 30 to 50 files before it writes a plan.

## The cause

`plan_goal` in `cli.py` called the planner with a limit written into the code, 240 seconds. It never looked at `agent_timeout`, which governs the calls inside a run, and the first planner call happens before any run exists.

Exit code 124 is not the model's. `execute` in `process.py` returns 124 itself when a call passes its time limit, 125 when the call's log has not grown for the idle timeout, and 126 when the log grows past its size limit. The old message printed the bare number, so nothing said which limit it was or where to change it.

## The setting

`planner_timeout` is a whole number of seconds from 1 to 14400, the same bounds as `agent_timeout`. Put it in the template, or pass `--planner-timeout SECONDS` to `goal`, `oneshot` or `wish`. The planner's limit is the first of these that exists:

1. `--planner-timeout`
2. the template's `planner_timeout`
3. the template's `agent_timeout`
4. 1800, the default `agent_timeout`

It is never 240 again, and it can be lower than 240 only if you set it so. The value is saved in the plan, so the planners inside a run (the wave planner, the design-direction planner, a rescue diagnosis by the planner) use it too. Without it they use `agent_timeout`, as before. The planner prompt's `Run limits` line shows `planner_timeout_seconds` only when one is set.

## What was checked

| Role | Limit before | Limit now |
| --- | --- | --- |
| Goal planner (`goal`, `oneshot`, `wish --start`) | 240 s, fixed | flag, else `planner_timeout`, else `agent_timeout` (1800) |
| Wave planner, design-direction planner, rescue diagnosis by the planner | `agent_timeout` | `planner_timeout` if the plan sets one, else `agent_timeout` |
| Worker, reviewer, judges, design-direction worker | `agent_timeout` | unchanged |
| Brief writer of `wish` | 900 s, fixed | unchanged, and the message says it is fixed |
| `doctor --live` probe | 45 s, fixed | unchanged, on purpose |

Every call inside a run goes through one function, so no role in a run had a shorter cap of its own.

## The messages

A call the controller ended is now said in words, by the goal planner, the pursuit judge and planner, the design-direction planner, judge and worker, the rescue diagnosis, the worker, the reviewer and the brief writer. They share one helper in `process.py`.

- 124: `The planner timed out after 240 s, its time limit (planner_timeout in the template; raise it there or with --planner-timeout)`. Inside a run the setting named is `agent_timeout` or `planner_timeout` in the plan, and the message adds that a run keeps its plan, so the fix is a new plan added as a new run.
- 125: `The judge was stopped by the idle watchdog after 900 s without output, its idle timeout (budgets.idle_timeout in the plan; ...)`.
- 126: `The reviewer was stopped at its output limit: its log grew past 16 MB (budgets.max_log_bytes in the plan; ...)`. The goal planner and the brief writer call it a fixed limit of the call, because no setting changes it there.

Any other exit code keeps its old text.

## Tests

`tests/test_release_0194_planner_timeout.py` uses stand-in providers only: a patched `invoke`, a `command` planner that sleeps past a small `planner_timeout`, and scripted pursuit, exploration and rescue fixtures. The version checks of the 0.19.2 and 0.19.3 modules now compare the version files with each other instead of with a fixed number, and two 0.19 tests (worker stall, rescue diagnosis) name the new wording.
