# Nightweaver 0.6 research and operator guide

Research cutoff **18 November 2026**. Nightweaver owns the Windows worktree, milestone loop, checks, retry decisions and acceptance records. Claude Code and Codex can work inside that loop. The optional AGTX adapter runs a separate contender inside WSL when an operator explicitly includes it in a benchmark.

## What informed the ranking

I reviewed the existing 0.5 capabilities, the last private browser-game benchmark, release notes, upstream implementation guidance and evaluation research. I ranked a recurring failure that can stop a whole run above convenience features. Next came checks that can distinguish working software from plausible screenshots, then evidence that makes comparisons and recovery trustworthy. Ranks express engineering judgment for this project. They are not adoption counts or measured effect sizes.

## The ranked twenty

| Rank | Improvement now in Nightweaver | How to observe it and why it matters |
| ---: | --- | --- |
| 1 | Pinned visual regression checks | A `visual_match` step compares the selected element against a SHA-256-pinned PNG. It records the changed-pixel count, total pixels, actual capture and a difference image on mismatched pixels. An operator sets the tolerance. This catches loss of approved art direction. [Playwright visual comparisons](https://playwright.dev/docs/test-snapshots) |
| 2 | Accepted-commit browser replay | `replay-browser RUN` checks the exact accepted milestone in a fresh independent local clone per gate, applies its timeout, and writes separate receipts. It works on older runs with saved browser contracts. [SWE-bench evaluation](https://www.swebench.com/SWE-bench/guides/evaluation/) |
| 3 | Browser ownership in the AGTX comparison adapter | The coordinator prompt and trial-specific worker instructions assign declared browser gates to Windows. The normal Nightweaver verifier still requires the merged implementation to pass the operator's gates. [AGTX OneShot procedure](https://github.com/fynnfluegge/agtx/blob/v1.0.6/skills/oneshot/SKILL.md) |
| 4 | Interactive approval detection in an external AGTX trial | Two consecutive observations of the Codex permission menu on the trial's private tmux socket interrupt the coordinator. The adapter saves the reason and returns the unavailable status. The benchmark excludes that pair from quality scoring. Other interactive menus can still reach the deadline. [AGTX board and pane tools](https://github.com/fynnfluegge/agtx/blob/v1.0.6/CLAUDE.md) |
| 5 | Recovery of unmerged AGTX drafts | On interruption or incomplete export, a temporary Git index captures committed, modified and new nonignored files in each registered task worktree. The adapter transfers binary patches with SHA-256 verification into its private evidence directory. Only a completed board merge can enter the outer checkout. [Git worktrees](https://git-scm.com/docs/git-worktree) · [Git diff](https://git-scm.com/docs/git-diff) |
| 6 | Accessibility tree assertions | An `aria` step compares the rendered accessible subtree to an inline YAML snapshot. A mismatch saves the actual subtree when the locator resolves uniquely. This catches name, role and hierarchy regressions, subject to the operator's assertions. [Playwright ARIA snapshots](https://playwright.dev/python/docs/aria-snapshots) |
| 7 | User-facing browser locators | Click, fill and assertion steps support role and accessible name, field label and test ID. The existing CSS form remains supported. An accessible name change can now fail the same interaction a user relies on. [Playwright locators](https://playwright.dev/python/docs/locators) |
| 8 | Mobile and touch emulation | Each viewport can set mobile layout, touch capability and pixel density. A narrow desktop window and a touch-capable mobile browsing context can now exercise different app behavior. [Playwright device emulation](https://playwright.dev/python/docs/emulation) |
| 9 | Appearance and accessibility preferences | Set color scheme, reduced motion and forced colors per viewport. A gate can test the same journey under different user preferences. [Playwright media emulation](https://playwright.dev/python/docs/emulation) |
| 10 | Network health and request budgets | Opt into HTTP failure detection, request counts and a maximum request budget. The recorder covers HTTP(S) requests observed during the journey and omits query strings from its generated network diagnostics. This catches broken assets even when the main document loads. [Playwright network events](https://playwright.dev/python/docs/network) |
| 11 | Model-free plan preflight | `preflight PLAN` resolves the source, reads the pinned context, validates visual references, checks Git identities and configured routes, and launches each requested browser channel against a tiny local page. Use this before a long run. [Claude Code status diagnostics](https://github.com/anthropics/claude-code/releases/tag/v2.1.327) · [Playwright browsers](https://playwright.dev/python/docs/browsers) |
| 12 | Worker limit classification | Newly recorded worker rejections retain their exit code. A terminal rejection distinguishes the adapter's reserved deadline, inactivity and output-budget codes. Older receipts without a code retain their historical classification. [Agent Orchestrator lifecycle records](https://github.com/OrchestratorInc/agent-orchestrator/releases/tag/v0.15.3) |
| 13 | Repair effectiveness by milestone | Run metrics and HTML reports expose first-pass and repaired acceptances. A repair requires a recorded rejection and a subsequent milestone acceptance. A provider invocation count alone cannot show that a fix worked. [Inspect evaluation logs](https://inspect.aisi.org.uk/eval-logs.html) |
| 14 | Browser and gate timing | Each gate receipt includes monotonic runtime. Browser receipts give elapsed milliseconds per attempted step and viewport, including a failed step. Run metrics expose the slowest measured gate. [Playwright trace viewer](https://playwright.dev/python/docs/trace-viewer) |
| 15 | Conflicting verification results on identical inputs | Metrics flag a gate only when both pass and fail were observed on the same recorded Git tree and gate-contract digest in one run. This is a lead for investigating timing or environmental variation. [Playwright retries](https://playwright.dev/docs/test-retries) |
| 16 | Exact paired benchmark test | JSON and standalone HTML report discordant pairs and the two-sided exact binomial p-value on their direction. Ties and inconclusives contribute no directional evidence. Repeats of the same task may be correlated, and many pairwise comparisons inflate false positives. [SciPy exact binomial test](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.binomtest.html) |
| 17 | Benchmark preview with budgets | `benchmark preview SUITE` uses the same plan preparation, mode conversion, seed and shuffle as creation. Inspect all frozen baselines, task and route hashes, configured outer call caps and summed trial time budgets before registering anything. [Inspect evaluation sets](https://inspect.aisi.org.uk/eval-sets.html) |
| 18 | Online SQLite backup | `db-backup FILE` copies live committed records through SQLite's online backup API, validates the result and publishes to a new filename atomically. Keep private worktrees, logs, context packs and evidence separately when backing up an entire run. [SQLite online backup](https://www.sqlite.org/backup.html) |
| 19 | Runtime integrity checks | `db-check` opens the live database or a saved copy read-only, verifies SQLite integrity, checks event-to-run references and validates stored JSON syntax. It provides a nonzero exit on failure. [SQLite integrity check](https://www.sqlite.org/pragma.html#pragma_integrity_check) |
| 20 | Reproducible Windows CI dependencies | Checkout, Python setup and .NET setup use verified full commit SHAs from maintained major releases. Checkout drops the workflow credential after fetching. The Windows job installs the browser extra, runs the suite and builds the WPF desktop app. [GitHub Actions secure use](https://docs.github.com/en/actions/reference/security/secure-use) · [Checkout](https://github.com/actions/checkout/releases/tag/v7.0.1) · [Python setup](https://github.com/actions/setup-python/releases/tag/v7.1.0) · [.NET setup](https://github.com/actions/setup-dotnet/releases/tag/v6.1.0) |

## Windows field evidence

A native Nightweaver run extended an existing illustrated browser game with a watch log and locally saved notes. Nightweaver used Claude Code for two worker calls. Both milestones passed on the first attempt in 70.4 seconds with zero interventions. Fresh clones of the accepted commit passed all three final browser gates, each on desktop and phone. The standalone file also completed all six letter orders on both viewports and retained its watch note after reload. A separate deterministic native run deliberately failed its first check, repaired the first milestone and completed the second with three worker attempts.

An independent AGTX comparison trial encountered a real interactive request for permission to write shared Git worktree metadata. The new detector ended the trial in 234.5 seconds and recovered a 14,566-byte unmerged patch. Windows recorded an inconclusive provider/environment outcome. These two field tests had different tasks and starting commits, so their times cannot rank the two orchestrators.

## Using the new checks

Install the browser dependencies and Chromium on the Windows machine that runs the gates.

```powershell
python -m pip install -e ".[browser]"
python -m playwright install chromium
python -m nightweaver preflight .\plan.json
python -m nightweaver benchmark preview .\suite.json
python -m nightweaver replay-browser $runId --milestone 1 --gate "Open the archive"
python -m nightweaver metrics $runId
python -m nightweaver db-backup .\nightweaver-backup.sqlite3
python -m nightweaver db-check --file .\nightweaver-backup.sqlite3
```

This fragment belongs in a browser gate's `browser` object.

```json
{
  "page": "index.html",
  "network": {"require_success": true, "max_requests": 25},
  "viewports": [
    {"name": "phone-dark", "width": 390, "height": 844, "is_mobile": true, "has_touch": true,
     "device_scale_factor": 2, "color_scheme": "dark", "reduced_motion": "reduce"},
    {"name": "desktop-contrast", "width": 1440, "height": 900, "forced_colors": "active"}
  ],
  "steps": [
    {"action": "click", "locator": {"role": "button", "name": "Open archive"}},
    {"action": "fill", "locator": {"label": "Search"}, "value": "ferry"},
    {"action": "aria", "locator": {"role": "main"}, "value": "- heading \"Archive\" [level=1]"}
  ]
}
```

For a visual check, commit a PNG of an approved, stable element and obtain its digest with `(Get-FileHash .\baselines\mark.png -Algorithm SHA256).Hash.ToLowerInvariant()`. Add a step with action `visual_match`, a selector or locator, and the value fields `baseline` and `sha256`. `channel_delta` allows an RGB channel difference from 0 through 255. `max_changed_ppm` allows changed pixels per million. Both default to zero. A differently sized reference fails. Use separate gates for different viewport-specific reference images. Capture the reference on the intended browser and font stack. A matching image measures agreement with the approved reference. Choosing that reference remains an art-direction decision.

A native run uses `nightweaver add PLAN` followed by `nightweaver run RUN`. AGTX participates only when explicitly configured as an external command in a benchmark. A saved AGTX draft has no effect on a Nightweaver result branch.
